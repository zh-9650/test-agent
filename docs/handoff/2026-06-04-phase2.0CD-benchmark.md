### 3. Phase 2.0D — ActionResult Extension + Screenshot-on-Demand (`e25ebbb`)

**Files**:

**Goal**: Match browser-use's `ActionResult` for parity. Screenshot-on-demand is a token-cost optimization (screenshot = 3000-4000 tokens; AXTree-only = 200-400 tokens).

**Behavior change**: `L2_OBSERVE_SCREENSHOT=1` (old behavior, screenshot at every observe) is now off by default. LLM must explicitly invoke `screenshot_on_demand` tool. Backward compatible via env.

## Key Decisions

| Decision | Why | Trade-off |
|----------|-----|-----------|
| Launch Phase 2.0C without trigger eval | CDP modules have zero runtime cost when dormant; trigger measurement is one env-flip away | If failure rate < 30%, this is YAGNI infra |
| Screenshot-on-demand default OFF | 90% token cost saving when LLM doesn't need vision | LLMs may miss visual bugs without reminder; mitigated by explicit tool |
| ActionResult status enum | Replaces bool `success` with 5-state for nuanced LLM reasoning | All 14 tools updated; back-compat via `success` field still set |
| Commits split 3 ways (not 1 mega) | Cleaner history, each phase independently revertable | More merge friction if any single commit is bad |
| Cleaned debug scripts not committed | They're local debugging artifacts | None — handoff references the bug fixes they discovered |

## Warnings / Gotchas

- **Do NOT `Get-Process chrome* | Stop-Process -Force`**. The user has a real Chrome running. The right way to clean up benchmark processes: kill only the Python process + headless Chromium (`chrome-headless-shell` or `chromium`). Crashed the user's browser once doing this.

- **MiMo v2.5 image format must be Anthropic-native**. If you see `LLM调用失败: connection was closed in the middle of operation` — it's the image format, not the network.

- **DB must be initialized before any `graph.ainvoke()` call**. `init_database()` is idempotent but takes ~2s on first run.

- **Phase 2.0D screenshot-on-demand is OFF by default**. If LLM behavior changes (e.g. less visual context), set `L2_OBSERVE_SCREENSHOT=1` to restore old behavior.

- **CDP modules are dormant**. `get_cdp_session()` is only called from CDP-backed tool paths that don't exist yet. No runtime cost in current execution path.
