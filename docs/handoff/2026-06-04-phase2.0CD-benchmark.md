## 3. Phase 2.0D — ActionResult + Screenshot-on-Demand (`e25ebbb`)

### ActionResult extension (`core/interfaces.py`)
8 new fields for browser-use parity:
- `status: Literal[success, failure, timeout, not_found, inconclusive]`
- `extracted_content: str` — post-exec content (LLM-readable)
- `long_term_memory: str` — next-step suggestion
- `candidates: list[dict]` — failed locator alternatives
- `include_in_memory: bool` — exclude temp tools
- `duration_ms: int`
- `evidence: dict` — screenshot path / network / stack summary
- `is_terminal()` method

### Screenshot-on-demand (`agents/ui/execution_graph.py`)
- **Before**: every `observe_node` took a screenshot (3000-4000 tokens)
- **After (default `L2_OBSERVE_SCREENSHOT=0`)**: no screenshot, LLM must invoke `screenshot_on_demand` tool
- **Backward compat**: set `L2_OBSERVE_SCREENSHOT=1` to restore old behavior
- `_fast_assert` now also checks `action_result.status` (failure/timeout/not_found) + injects `long_term_memory` into reasoning

### New env vars
| Var | Default | Effect |
|-----|---------|--------|
| `L2_OBSERVE_SCREENSHOT` | `0` | Take screenshot at every observe (1=always, 0=on-demand) |
| `L2_SCREENSHOT_COMPRESSED` | `1` | JPEG compress screenshots (0=raw PNG) |

### ⚠️ May correlate with 0/10 regression
WV-004 (Google Flights) ran 1 step and `fail`-ed — LLM had no visual context to understand the form. WV-006 (BBC News) ran 8 steps and `fail`-ed — agent saw headline in AXTree but didn't generate textual answer. Both patterns are consistent with reduced visual context. **Next step: re-run with `L2_OBSERVE_SCREENSHOT=1` for A/B comparison.**

## 6. System Problems (from 10 benchmark runs)

10 tasks: 4 `fail` (LLM judge caught agent issues), 6 `error` (graph exceptions). `data/webvoyager_report_v3.md` has full per-task detail.

### 6.1 Anti-bot / scope limits (5/10 sites)
Not bugs, not fixable by us:
| Task | Site | Blocker |
|------|------|---------|
| WV-002 | Walmart | "Robot or human?" CAPTCHA — must press-and-hold |
| WV-003 | Booking.com | Genius sign-in popup blocks form interaction |
| WV-005 | GitHub | (may be network/protocol, not anti-bot — see 6.3) |
| WV-008 | Wikipedia | (also see 6.3 — long run, may be timeout) |
| WV-010 | OpenTable | `net::ERR_HTTP2_PROTOCOL_ERROR` (CDN-side block) |

These 5/10 are an irreducible scope limit. Future benchmark suites should include "anti-bot-friendly" sites to get a non-zero baseline.

### 6.2 Agent behavior issues (4/10 — fixable)
- **WV-003 shortcut**: agent navigated to `https://www.booking.com/searchresults.html?...` with query params instead of filling form. **Fix**: system-prompt rule "Never navigate directly to result URLs; always interact with the form."
- **WV-004 zero-input**: ran 1 step on Google Flights homepage and gave up. **Fix**: similar prompt rule; possibly need screenshot for complex forms.
- **WV-006 no-report**: agent navigated to BBC News, found headline in AXTree, called `mark_task_complete` with no `extracted_content`. Judge got empty `agent_answer` (runner does `extracted_content or error`, both empty). **Fix**: `mark_task_complete` should auto-extract page title/headline as `extracted_content`; or LLM should be required to call `extract` before mark.
- **WV-002 not-fixable**: Walmart CAPTCHA.

### 6.3 Silent errors (6/10) — needs investigation
**Current state (post-traceback fix, but pre-re-run)**: the tracebacks for these 6 errors were lost. Previous stderr file (`data/bench_v3_stderr.txt`, 1542 lines) is truncated mid-WV-009 and contains only `L2_NODE_EVENT` JSON lines (no exception traces). Per-task event counts:
| Task | L2 events | Duration | Implied failure point |
|------|-----------|----------|----------------------|
| WV-001 | 120 | 361s | Mid-run (likely assert LLM timeout) |
| WV-005 | **0** | 30s | Before graph started — browser launch / goto / setup |
| WV-007 | 60 | 215s | Mid-run (5 steps × 4 events) |
| WV-008 | 124 | 599s | Mid-run (timeout — duration near `max_steps * step_avg`) |
| WV-009 | 120 | 387s | Mid-run |
| WV-010 | **0** | 2s | Before graph started — most likely `page.goto` immediate fail |

**Likely causes** (ordered by probability):
1. **WV-005, WV-010 setup failures** (0 events, 2-30s): probably `init_database()` not yet warm + first `page.goto` timeout, OR browser launch race. Fix: explicit `await page.goto(..., wait_until="networkidle", timeout=60000)` + retry.
2. **WV-008 599s timeout**: hit `max_steps=15` × LLM judge slowness. Fix: bump `max_steps` or add `time_budget_s` per task.
3. **WV-001/007/009 mid-run assert timeout**: `assert_node` LLM call exceeded Anthropic SDK timeout. Fix: add per-node timeout config (currently 5-30s per call is normal, but spike to 60s+ kills the graph).
4. **Schema validation mismatch** (speculative): previous stderr mentioned `Field required: reasoning` for `AssertionResult`. Phase 2.0D added `status` field; if any node still produces a legacy AssertionResult without reasoning, validation fails silently. **Verify with the new traceback capture** on next re-run.

### 6.4 Other system observations
- **Long task durations** (avg 241s, max 600s): judge adds 5-10s, but LLM decide+execute cycle is the bulk. 100 cases = 6-7 hours — iteration is slow. Parallel executor (`core/parallel_executor.py` from 2.0C) could halve this once enabled.
- **Judge only sees last screenshot** (line 281 of runner.py): trajectory-blind. If the agent's last step was right but page redirected, judge can't tell. Acceptable trade-off for now.
- **Dry-run is partial** (runner.py:238-247): only calls `extract_page_semantics`, doesn't build graph. So `--dry-run` validates "page loads" not "graph runs".

## 8. Warnings / Gotchas

- **Do NOT `Get-Process chrome* | Stop-Process -Force`**. User has a real Chrome. Kill only the Python process + headless Chromium (`chrome-headless-shell` or `chromium`).
- **MiMo v2.5 image format must be Anthropic-native** (`{"type":"image","source":{"type":"base64",...}}`). If you see `LLM调用失败: connection was closed in the middle of operation` — it's the image format, not network.
- **DB must be initialized before any `graph.ainvoke()` call**. `init_database()` is idempotent but takes ~2s first run.
- **Screenshot-on-demand is OFF by default** (2.0D change). For visual-heavy sites, set `L2_OBSERVE_SCREENSHOT=1`.
- **CDP modules are dormant** (2.0C). No production path uses them yet.
- **Benchmark is slow** (avg 241s/task). 100 cases = 6-7h. Plan accordingly.
- **Anti-bot sites are scope limits**, not bugs. CAPTCHA / ERR_HTTP2 / popup blockers are irreducible.
