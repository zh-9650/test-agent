## 6. 架构变更记录

### Graph 拓扑变化（B3.1）

```
旧: START → observe → decide → execute → assert → record → (observe | END)
```

## 8. 已知风险

1. **未 commit 风险**: Phase 2.0A + 2.0B 代码全在 working tree。建议 commit Phase 2.0A 部分（保留所有改动），或统一 commit 后继续。
2. **scratch + logs 目录**: 40+ 调试脚本 + 运行日志含硬编码密码/URL，commit 前需清理。
3. **B1.1 启发式准确率**: `_should_auto_inject_password()` 基于关键词匹配，边界 case（如混合步骤"输入用户名和密码"）可能误判。建议跑 50 case 后评估准确率，准确率 < 90% 则叠加 RAG memory 方案。
4. **B1.2 二次确认假阴性**: 如果页面确实变了但 `detect_changes` 没捕获（如仅 CSS 变化），`mark_task_complete` 会被错误降级。当前安全设计降级为 `inconclusive` 而非 `fail`，保留人工判定空间。
5. **B2.1 脱轨纠正阈值**: 连续 2 步无变化即触发。某些场景（如填写长表单）页面确实会连续多步无大变化，可能导致误触发。后续可调为可配置参数 `DERAIL_STEPS=3`。
