## 结论

首个 v2 解析黄金集不能只放一份 PRD，也不能把既有业务理解和旧用例混入输入。
建议冻结为四个相互隔离的集合：

1. **生成输入集**：PRD、产品答复、待澄清问题、接口文档、原型资源闭包和思维图。
2. **观察输入集**：选定的真实系统响应快照，只表示当前行为，使用前必须脱敏。
3. **隐藏评测集**：既有业务理解、测试条件和用例，只供盲测评分，禁止进入生成上下文。
4. **明确排除集**：账号、cookie、token、操作脚本、执行日志和与绩效切片无关的资料。

冻结对象以原件 SHA-256 为身份。大文件不复制进 `test_agent` 仓库；仓库只保存
manifest、结构黄金断言和脱敏规则。

## 结构黄金断言

### DOCX

`SRC-NORM-001` 的 OOXML 盘点结果：

- 段落：773
- 表格：15
- 表格行：120
- 单元格：558
- drawing：31
- `word/media` 图片：31，全部为 PNG
- 文本框：0
- 超链接：0
- 批注：0

当前 `api/utils.py` 只拼接 `doc.paragraphs`，因此会静默丢失15张表、558个单元格和
31张图片。v2 DOCX 解析器在这些结构没有全部得到处置前不能报告 complete。

### Markdown/API

至少保留：

- 标题路径和目录关系。
- 表格的行列结构。
- 代码块和 JSON 示例。
- endpoint、method、参数、字段、枚举和说明的邻接关系。
- 章节定位，尤其是4.2、4.3、4.4、4.5、4.6及权限附录。

### HTML原型

至少保留：

- 页面和资源清单。
- 页面可见文字及层级。
- 输入、选择、上传、弹窗、Tab和自定义点击区域。
- 页面间导航、状态变体和隐藏/显示关系。
- 控件所在HTML文件及稳定定位。
- 未进入语义提取的资源也必须有忽略理由。

### 观察JSON

至少保留：

- 响应层级和数组关系。
- 状态、阶段、角色、动作、消息和跨模块标识。
- 同一业务对象跨文件的一致假名ID。
- 原始值与脱敏值的不可逆映射边界。

## 明确排除

- `.playwright-*` 中的登录态、缓存和执行日志。
- 账号密码、token、cookie、浏览器 profile。
- `work` 下自动生成的旧业务理解、测试条件和测试用例作为生成输入。
- 与绩效首个切片无关的财务、安全、服务模块原型和接口资料。
- 8,269个 SVG 的全目录盲扫；只保留入口页面资源闭包及显式引用清单。
- `prd-copy-temp.docx`：与主 PRD 等体积的临时副本，避免重复来源污染。
