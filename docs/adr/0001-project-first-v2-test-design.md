# 先在项目中验证 v2 用例生成内核

v2用例生成需要正式模型、确定性覆盖编译、失效重算和质量门；这些约束如果先实现为共享Skill，仍可能被AI跳过或重新解释。因此先在`test_agent`中以独立入口或feature flag实现并通过真实样本的v1/v2盲测，再从已验证的项目接口和工作方式提炼`test-design-studio` Skill。当前里程碑不同时修改Runtime、执行Memory或默认公共路由；脚本执行和直接执行保留为后续消费同一冻结测试规格的不同适配方向。

v2 的项目内边界从原始资料接入开始，而不是从人工预先整理好的业务基线开始。固定顺序为：
`原始资料 → 保真解析 → 解析质量门 → 证据声明 → 业务基线草案 → 人工确认 → 正式模型 → 覆盖义务 → 用例投影`。
人工确认只负责业务语义和冲突裁决，不能代替解析完整性检查。任何资料被静默丢失、
结构被压平且无法定位，或解析结果处于 partial/failed 状态时，都必须阻止后续生成。
