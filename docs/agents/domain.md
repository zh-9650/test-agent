# Domain Docs

本仓库使用单上下文领域文档布局。

## 探索代码前

- 读取根目录 `CONTEXT.md`，使用其中的规范术语。
- 读取 `docs/adr/` 中与当前改动有关的架构决策。
- 如果文件不存在，继续工作，不为填充目录而创建空文档。

## 文件布局

```text
/
├─ CONTEXT.md
└─ docs/
   └─ adr/
```

`CONTEXT.md`只保存领域词汇及其精确定义，不保存实现细节、开发计划或临时结论。

`docs/adr/`只保存难以逆转、存在真实取舍且未来维护者无法从代码直接理解的架构决策。

## 使用规则

- Issue标题、测试名称、设计规格和代码中的领域概念采用`CONTEXT.md`中的词汇。
- 不确定的新术语先通过领域建模确认，再写入`CONTEXT.md`。
- 如果新方案与现有ADR冲突，必须明确指出并决定是否废弃或替代旧ADR，不能静默覆盖。
